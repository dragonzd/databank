# Step 1: 产品经理 (Alex) — 数据银行系统平台产品设计方案

## 1. 需求理解

数据银行的核心诉求是构建一个「数据资产化操作系统」——它不是做一个应用或平台，而是定义数据从产生、确权、定价、流通到金融化的底层协议层。它需要同时解决权属断裂（谁的数据）、价值断裂（谁赚钱）和流动断裂（数据怎么安全流动）三个结构性问题，并以"类银行"的商业模式把数据当作可经营的资产来运作。

## 2. 用户价值分析

| 用户角色 | 核心痛点 | 解决后的价值 | 影响范围 |
|---------|---------|-------------|---------|
| **数据所有方（个人/家庭/企业）** | 数据沉默、无法变现、授权无门、隐私无保障 | 数据像存款一样生息，主权可控，持续产生被动收入 | 数亿个人 + 千万企业 |
| **数据鉴权方（设备/机构）** | 背书能力无法变现，信誉无法量化 | 公信力成为可交易资产，按数据使用量持续分润 | 万级机构 |
| **数据使用方（AI/金融/医疗/营销）** | 无合规数据可用、数据质量不可信、成本高企 | 合规可信数据按需获取，按 Token 付费，成本弹性可控 | 百万级企业 |
| **社会信用/评价体系** | 数据底座薄弱，静态滞后 | 多源实时可信数据支撑动态信用画像和评价更新 | 全社会 |

## 3. 功能范围界定

### MVP（P0 · 必须交付，M1-M12）

- 联盟链网络（Substrate 基座，DID+VC 身份，监管节点）
- 协议账户核心合约（三权分立，生命周期，纠纷仲裁基础）
- Token 发行与结算（1 Token=0.01 法币，发行/分账/计量/出入金）
- 边缘 SDK v0.1（本地加密存储，数据分块，基础同步）
- 鉴权方准入（注册、审核、信誉质押、基础分润）
- 基础管理后台（账户管理、交易查询、基础报表）
- 数据存款基础（活期存款，Token 利息，基础利率模型）

### V1.1（P1 · 产品化扩展，Y2-Y3）

- 数据沙箱服务上线（模型进场、数据不出域，容器沙箱 + 可信计量）
- 数据理财引擎（多源数据资产池）
- 数据资产入表服务工具
- 隐私索引服务（同态加密匹配）
- 用户门户 Web/App
- 开放 API 平台（含 SDK 文档）

### V2（P2 · 生态确立，Y4+）

- 数据交易所（挂牌/撮合/清算）
- 跨链互操作协议
- MPC 联邦学习平台
- 衍生品交易模块
- 全球多区域部署

## 5. 验收标准（MVP）

### 协议账户核心合约

- [ ] Given 数据所有方发起账户创建，When 提交 DID 和初始数据指纹，Then 协议账户在链上生成，返回所有权令牌
- [ ] Given 所有方授权使用方，When 设置使用权许可证（时间范围+数据范围+价格），Then 使用方可在许可范围内发起数据请求
- [ ] Given 纠纷发生，When 任一方提交仲裁请求，Then 自动按规则执行（冻结→仲裁→执行），全流程链上存证
- [ ] Performance: 账户创建 < 3s，许可证验证 < 500ms

### Token 结算

- [ ] Given 使用方消费数据，When 数据使用完成，Then 系统自动计量并触发分账（所有方 70%+鉴权方 20%+银行 10%），延迟 < 500ms
- [ ] Given 法币入金，When 支付确认，Then Token 一分钟内到账
- [ ] P99 结算延迟 < 500ms，零账实不符

### 边缘 SDK

- [ ] Given 用户在设备安装 SDK，When 数据产生，Then 自动加密分块存储至本地，DID 签名
- [ ] Given 数据同步指令，When 网络可用，Then 增量同步至指定存储节点，断点续传
- [ ] 支持平台：Android / iOS / Linux / 嵌入式（C SDK）
